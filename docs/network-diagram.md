## Visual Standard

Every per-site diagram in this file is split into two labelled boxes:

- **Old Network (legacy)** — this file's original content, sourced by hand over time. Kept as-is data-wise; not regenerated.
- **New Network (current)** — generated from `benarbejde/sites.csv` + `benarbejde/devices.csv` + `benarbejde/address_policy.json`, the actual single source of truth for the estate. Regenerated by `benarbejde/generate_network_diagrams.py` and checked for drift by the test harness (`ansible/at_have_ryggen_fri/`, check 14) — if you edit a New Network box by hand, the next harness run will flag it as stale.

**Shape = functional device class** (same shape means same class, in both boxes):

| Shape | Class | Type codes |
|---|---|---|
| `{{hexagon}}` | Network infrastructure | RTR, FWL, SWI |
| `[("cylinder")]` | Servers / compute / management | DCS, DCR, SVR, SRV, RDR, RRY, ANS, PBX, DNS, PRV, NAS, PVE, SBC, TAR, UFC, RAC |
| `(("circle"))` | Wireless access points | WAP |
| `(["stadium"])` | Endpoints / workstations | WKS, LAP, MBP, TAB, SUR, PHN, PRN, CAM, LCD, VCU, TVS, MAC, NIX, BPS |
| `>"flag"]` | Curveball / novelty devices — shape itself is the "look closer, read the label" flag | VND, MUS, PAY, COF, TEA, PMP, CLK, MIC, RAD, MOO, LIN, FCL, AST, TTY, BUS, CAR, JET, TRK, DON |

**Colour = old vs new**, applied once per box (not per site, not per node — 53 sites of per-site colour would be unreadable, and colourblind-unfriendly with it):

| Box | Fill | Notes |
|---|---|---|
| Old Network (legacy) | `#56B4E9` (sky blue) | Okabe–Ito colourblind-safe palette |
| New Network (current) | `#E69F00` (orange) | Okabe–Ito colourblind-safe palette |
| Issue flagged (`warn`) | `#D55E00` (vermillion) on `#000000` text | Distinct from the above under all common colour-vision deficiencies; replaces this file's former per-diagram ad-hoc `warn`/`net` colours, several of which were red/green pairs — a real colourblind hazard found during the 2026-07-13 audit, not a hypothetical one. |

**Unicode symbols, not icon fonts.** Specific-device identity within a class (☕ coffee machine, ☎ payphone, 🚌 tour bus, etc.) is a literal Unicode character prefixed to the node label — confirmed via a live kroki.io round-trip 2026-07-13 to render reliably with no external dependency. FontAwesome-class icon syntax (`fa:fa-x`) and Mermaid's newer `@{ icon: }` syntax were tested the same way and do **not** reliably render through this pipeline (unstyled CSS class with no attached webfont, or a silent fallback to a generic default shape) — do not use either. Real Cisco stencils are not an option (trademarked, and not portable through kroki regardless). Any device not yet assigned a symbol carries a literal `❓` placeholder pending sign-off — see `ansible/at_have_ryggen_fri/README.md`'s Backlog section.
